# Matriks cakupan fitur MikroTik MCP JavaScript

## Status saat ini

Implementasi JavaScript yang dikembangkan sendiri ini mendaftarkan **312 tool MCP**, mencakup **229 deskriptor resource RouterOS dengan jalur tetap**, **218 jalur API unik**, dan **8 kelompok fitur**. Sebanyak 56 resource hanya-baca; 173 resource menyediakan perubahan yang dibatasi allowlist. Repositori acuan mengiklankan **983 tool dalam 155 modul**. Angka ini tidak setara langsung: implementasi ini memakai pembaca resource generik dan tool perubahan bertahap untuk banyak menu. Proyek ini **belum memiliki kesetaraan fitur penuh** dan bukan salinan satu-per-satu.

Ketersediaan jalur RouterOS berbeda menurut model, versi perangkat lunak, paket terpasang, dan hak akun. `probe_router_capabilities` hanya menguji ketersediaan jalur secara best-effort dan tidak mengubah konfigurasi. Lihat [indeks dokumentasi repositori acuan](https://github.com/mikrotik-mcp/mikrotik-mcp/tree/master/docs/content/docs/reference/).

## Pengaman perubahan dan data

Perubahan konfigurasi membutuhkan `MIKROTIK_ALLOW_WRITES=true`, `MIKROTIK_ALLOW_HIGH_RISK_WRITES=true`, dan konfirmasi rencana yang persis. Diagnostik aktif juga memerlukan `MIKROTIK_ALLOW_ACTIVE_DIAGNOSTICS=true`; pemeliharaan destruktif memerlukan `MIKROTIK_ALLOW_DESTRUCTIVE_OPERATIONS=true`. Pembuatan/unduh/upload backup dan capture memakai gate write serta konfirmasi khusus; penghapusan backup/capture lokal dan penghapusan objek/versi S3 juga memerlukan gate destruktif. Bundle dukungan, webhook alert, serta capture RouterOS terkelola masing-masing memiliki opt-in terpisah dan mati default. Daftar S3, hapus key, dan purge versi memakai flag fitur terpisah; semuanya nonaktif di `.env.example`. Purge versi juga memerlukan `MIKROTIK_S3_ALLOW_VERSION_PURGE=true`.

Pembuatan backup mensyaratkan verifikasi sertifikat TLS karena passphrase dikirim melalui API RouterOS. SFTP hanya berjalan bila host key cocok dengan fingerprint SHA-256 yang dikonfigurasi. Direktori/file backup lokal memakai izin khusus pemilik, tetapi itu bukan jaminan enkripsi seluruh disk. Simpan passphrase terpisah. Tidak ada tool restore; transfer upload yang diuji bukan konfirmasi pemulihan.
